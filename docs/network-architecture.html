Network Architecture

P2P WebRTC via PeerJS. State sync at 60Hz (16.67ms). Client-authoritative hit detection. Socket.io server available as fallback when WebRTC fails.

Connection Architecture

PeerJS Signaling Server
ICE candidate exchange only

WebRTC DataChannel

Slot 1 • z = -15

Connection Sequence

  1. Host creates room: Generates 4-char code (e.g., "ABCD"), registers as peekshooter-ABCD
  2. Joiner connects: Enters code, PeerJS resolves to host's peer ID
  3. ICE exchange: Signaling server relays connection candidates
  4. DataChannel opens: Direct P2P established, signaling server no longer needed
  5. State sync begins: 60Hz bidirectional updates start

Any state → Disconnected: Peer disconnects, connection error, or user cancels

Message Protocol

Type Direction Frequency Purpose
state Bidirectional 60 Hz Stance, look direction, weapon, health
shoot Shooter → Opponent On fire Shot fired, hit position, target type
hit Shooter → Victim On hit Damage amount, body part
killed Victim → Shooter On death Kill confirmation for scoring
reset Bidirectional On round end Health/state reset for new round

State Message (60 Hz)

Sent every frame. Opponent interpolates toward target values at 15x speed to smooth jitter.

// Transmitted every 16.67ms { type: 'state', state: { crouch: 0.5, // 0 = standing, 1 = crouched lean: -0.3, // -1 = left, 1 = right strafe: 0.2, // -1 = left, 1 = right lookYaw: 0.15, // horizontal aim (radians) lookPitch: -0.08, // vertical aim (radians) weaponHand: 'right', weapon: 'assault_rifle', health: 85 } }

Shoot Message

Sent when player fires. Opponent uses this for muzzle flash and blood effects.

{ type: 'shoot', hitPlayer: true, // did shot hit opponent? hitCover: false, // did shot hit cover? hitX: -2.5, // world coordinates hitY: 1.3, hitZ: -12.8 }

Hit Message

Sent after shooter confirms hit via raycast. Client-authoritative: shooter determines hits.

{ type: 'hit', damage: 25, bodyPart: 'head' } // Victim responds with killed message when health depletes { type: 'killed' }

Socket.io Fallback

When WebRTC P2P fails (corporate firewalls, symmetric NAT), the Socket.io server relays all messages. Same protocol, different transport.

// server.js - Room and Player structures class Player { constructor(id, slot) { this.id = id; this.slot = slot; // 0 or 1 this.state = { crouch: 0, lean: 0, strafe: 0, health: 100 }; } } class Room { constructor(id) { this.id = id; this.players = new Map(); // max 2 this.state = 'waiting'; // waiting | playing | finished this.scores = [0, 0]; } }

Interpolation

Opponent state is interpolated at 15x speed to smooth network jitter while maintaining responsiveness.

// OpponentPlayer.update() - runs every frame update(deltaTime) { const lerpSpeed = 15; const t = Math.min(1, lerpSpeed * deltaTime); this.state.crouch += (this.targetState.crouch - this.state.crouch) * t; this.state.lean += (this.targetState.lean - this.state.lean) * t; this.state.strafe += (this.targetState.strafe - this.state.strafe) * t; this.state.lookYaw += (this.targetState.lookYaw - this.state.lookYaw) * t; this.state.lookPitch += (this.targetState.lookPitch - this.state.lookPitch) * t; }
