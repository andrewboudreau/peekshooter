ADR-001: Dual Character System (Procedural + GLTF)

Status: Accepted Date: 2025-01 Authors: Core Team

Context

PeekShooter needs character models for opponents. We had two options:

  1. Procedural only: Generate characters from code using primitive shapes
  2. GLTF only: Require external 3D models from Mixamo or similar

Decision

Implement both systems with automatic fallback:

  • Primary: Load GLTF/GLB models with Mixamo animations
  • Fallback: Procedural humanoid when assets unavailable

Rationale

  • Zero-config start: Game works immediately without downloading assets
  • Progressive enhancement: Add quality assets when ready
  • Development flexibility: Test gameplay without asset dependencies
  • Reduced barrier: New contributors can run the game instantly

Architecture

┌─────────────────────────────────────────────────────────────┐ │ Opponent.createMesh() │ └─────────────────────────────────────────────────────────────┘ │ ▼ ┌──────────────────┐ │ Try GLTF Load │ │ (async) │ └──────────────────┘ │ ┌───────────────┴───────────────┐ ▼ ▼ ┌──────────────────┐ ┌──────────────────┐ │ GLTF Success │ │ GLTF Failed │ │ → Replace mesh │ │ → Keep procedural│ │ → Setup anims │ │ │ └──────────────────┘ └──────────────────┘ │ │ └───────────────┬───────────────┘ ▼ ┌──────────────────┐ │ Same pose/stance │ │ interface works │ └──────────────────┘

Consequences

  • Positive: Game always works, quality scales with available assets
  • Negative: Two code paths to maintain, potential visual inconsistency
  • Mitigation: Both systems use same stance/pose interface

ADR-002: Bone Naming Convention

Status: Accepted Date: 2025-01

Context

Different 3D tools use different bone naming conventions:

System Hip Bone Left Thigh Spine
Mixamo mixamorig:Hips mixamorig:LeftUpLeg mixamorig:Spine
Unity Humanoid Hips LeftUpperLeg Spine
Blender Rigify spine thigh.L spine.001
Our Procedural pelvis hipL stomach

Decision

Use Mixamo naming exclusively - no custom naming, no mapping layer needed.

Why Mixamo?
  • Most widely used free rigging/animation source
  • Consistent naming across thousands of animations
  • Industry recognition - many developers already know it
  • Adobe backing ensures long-term availability
  • Direct compatibility with imported GLTF models

ADR-003: Animation System Architecture

Status: Accepted Date: 2025-01

Context

Three.js provides AnimationMixer for skeletal animation, but we need additional features:

  • Crossfade between animations
  • Procedural pose overlay (crouch/lean on top of idle animation)
  • Support for both GLTF and procedural models

Decision

Create a layered animation system:

┌─────────────────────────────────────────────────────────────┐ │ Final Bone Transforms │ └─────────────────────────────────────────────────────────────┘ ▲ │ additive blend ┌─────────┴─────────┐ │ │ ┌──────────▼──────────┐ ┌──────▼──────────┐ │ Base Animation │ │ Pose Overlay │ │ (idle, walk, etc) │ │ (crouch, lean) │ │ │ │ │ │ AnimationMixer │ │ Procedural │ └─────────────────────┘ └─────────────────┘

Components

Component Responsibility
MixamoCharacterLoader Load GLTF models, extract skeleton, remap bone names
AnimationController Wrap AnimationMixer, handle crossfade, apply pose overlays
MixamoBoneMap Bidirectional bone name mapping (Mixamo ↔ internal)
HumanoidFactory Generate procedural fallback model with compatible rig

Pose Overlay System

Stance adjustments (crouch, lean) are applied after the base animation:

// In animation loop
animController.update(deltaTime);  // Updates base animation

// Apply stance modifications additively
animController.applyPoseOverlay({
    'mixamorig:Spine': { x: crouchAmount * 0.3 },
    'mixamorig:LeftUpLeg': { x: crouchAmount * 0.8 },
    'mixamorig:RightUpLeg': { x: crouchAmount * 0.8 },
}, 1.0);

This allows the idle breathing animation to continue while the character crouches.

ADR-004: Asset Pipeline (FBX → GLB)

Status: Accepted Date: 2025-01

Context

Mixamo exports FBX format, but Three.js GLTFLoader only supports GLTF/GLB.

Decision

Use Blender as a conversion tool via Python script:

npm run convert-assets  # Batch converts all FBX → GLB

Why GLB over FBX?

Aspect FBX GLB
Format Proprietary (Autodesk) Open standard (Khronos)
Three.js Support Requires FBXLoader (larger) Native GLTFLoader
File Size Larger Smaller (binary + Draco compression)
Web Optimized No Yes (designed for web)

Workflow

Engineering Design Review: Animation System

System Overview

The animation system enables Mixamo-rigged characters to be used in PeekShooter with full support for the game's analog stance mechanics (crouch, lean, strafe).

Design Goals

  1. Drop-in Mixamo support: Load any Mixamo character/animation without modification
  2. Graceful degradation: Work without external assets
  3. Familiar conventions: Use industry-standard bone names
  4. Pose blending: Layer procedural stance on animated base

Data Flow

User Input (WASD/QE) │ ▼ ┌───────────────────┐ │ Stance State │ crouch: 0-1 │ (TransformComp) │ lean: -1 to 1 └───────────────────┘ strafe: -1 to 1 │ ├─────────────────────────────────┐ ▼ ▼ ┌───────────────────┐ ┌───────────────────┐ │ GLTF Model Path │ │ Procedural Path │ ├───────────────────┤ ├───────────────────┤ │ AnimationMixer │ │ HumanoidFactory │ │ plays base clip │ │ setPose() │ │ + │ │ │ │ applyPoseOverlay │ │ │ │ adds crouch/lean │ │ │ └───────────────────┘ └───────────────────┘ │ │ └─────────────┬───────────────────┘ ▼ Final Render

Key Interfaces

// Loading a character
const model = await MixamoCharacterLoader.load('character.glb');
// Returns: { root, bones, meshes, skeleton, animations, hitboxes }

// Setting up animation
const anim = new AnimationController(model.root);
anim.addBones(model.bones);  // Register bones for pose overlay
anim.addClip('idle', model.animations[0]);
anim.play('idle');

// In game loop
anim.update(deltaTime);
anim.applyPoseOverlay({
    'mixamorig:Spine': { x: crouchAmount * 0.3 },
    'mixamorig:Spine1': { z: leanAmount * 0.15 },
}, 1.0);

Future Considerations

  • Animation state machine: Transition rules between clips (idle→walk→run)
  • IK system: Feet placement, weapon aiming
  • Retargeting: Apply animations to different skeleton proportions
  • LOD: Simplified rigs for distant characters
